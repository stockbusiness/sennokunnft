# 法務文書の版管理（利用規約・プライバシーポリシー・特定商取引法に基づく表記）

**版**: 1.0 / **作成**: 2026-08-19 / **対象**: 運営者・開発者

---

## 1. なぜ普通のコンテンツと分けるのか

作品の説明文なら、直したら直った内容だけが残っていればよい。
法務文書は違って、**過去にどの版が有効だったか**が意味を持つ。

- 返金や苦情の場面で「そのご注文の時点では、こう書いてありました」と示せる必要がある
- 特商法の表記は**販売前に掲げる義務**がある。掲げていない状態で売ると、販売そのものが法に触れる
- 「あとから静かに書き換えられる」文書は、書いてあることの証明力を持たない

したがってこの機能は、**編集機能ではなく版管理**として作ってある。

---

## 2. 決めたこと

| 事項                   | 決定                                   | 理由                                                                      |
| ---------------------- | -------------------------------------- | ------------------------------------------------------------------------- |
| 公開済みの版の書き換え | **できない**                           | 書き換えられると、過去の版が失われ、上のことが成り立たない                |
| 削除                   | **できない**（口を作らない）           | 消せると、いつか「古いから」と消される。困るのは消したあと                |
| 状態                   | `draft` / `published` の 2 つだけ      | 「施行中」を状態にすると、日付が来ても誰かが切り替えるまで変わらない      |
| 「いま適用中」         | **施行日と現在時刻から毎回決める**     | 予約公開があるので「公開済み＝いま有効」ではない                          |
| 下書き                 | 種類ごとに **1 つだけ**（部分UNIQUE）  | 2 つあると、どちらを直しているのか操作する人に分からない                  |
| 版番号                 | 種類ごとの連番（1 から）               | 「規約 第3版」と言えるようにする。表全体の通し番号にしない                |
| 特商法の中身           | **12 項目の欄**（自由文 1 枚にしない） | 抜けているかどうかを機械が判定できる                                      |
| HTML                   | **保存の時点で断る**                   | 描画側で無視するだけだと、別の描画経路（メール・PDF）ができたときに流れる |
| 施行日                 | 過去にできない／現行版より後           | さかのぼれると、過去の注文に紐づく「その時点の版」が入れ替わる            |

### 権限

| 操作             | 必要な権限      | オーナーの印                 |
| ---------------- | --------------- | ---------------------------- |
| 版の一覧を見る   | `legal.view`    | 不要（閲覧者も可）           |
| 下書きを保存する | `legal.edit`    | 不要（運営スタッフが書ける） |
| **公開する**     | `legal.publish` | **必要**                     |

⚠️ 公開した版は取り消せず、書いた内容は購入者への約束になる。
**書く人と決める人を分ける**ため、公開だけをオーナーに限っている。

## 3. データ

`legal_document_versions`（migration `20260819130000_legal_documents`）。

| 縛り                                                       | 何を防ぐか                                                                                                                                                 |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `legal_document_versions_kind_valid`                       | 知らない種類の行                                                                                                                                           |
| `legal_document_versions_status_valid`                     | 知らない状態の行                                                                                                                                           |
| `legal_document_versions_published_complete`               | 施行日・公開日時・公開者の欠けた「公開済み」。あると、施行中の版を選ぶ問い合わせがそれを飛ばし、画面には「公開済み」と出ているのに利用者には古い文が見える |
| `legal_document_versions_body_shape`                       | 本文と特商法の項目が両方入った行（どちらが表示されるか実装依存になる）                                                                                     |
| `legal_document_versions_kind_version_key`                 | 同じ種類での版番号の重複                                                                                                                                   |
| `legal_document_versions_one_draft_per_kind`（部分UNIQUE） | 下書きが 2 つ以上                                                                                                                                          |
| `legal_document_versions_effective_from_key`（部分UNIQUE） | 同じ瞬間に 2 つ施行される（どちらが有効かが並び順まかせになる）                                                                                            |

⚠️ 部分UNIQUE は Prisma のスキーマでは表せない。**マイグレーションが正**。
この表を作り直すときは、必ず持っていくこと。

## 4. API

| メソッド | 経路                                | 権限                                       |
| -------- | ----------------------------------- | ------------------------------------------ |
| `GET`    | `/api/v1/legal/:kind`               | 公開（認証不要）。**施行中の版だけ**を返す |
| `GET`    | `/api/v1/admin/legal/:kind`         | `legal.view`                               |
| `PUT`    | `/api/v1/admin/legal/:kind/draft`   | `legal.edit`                               |
| `POST`   | `/api/v1/admin/legal/:kind/publish` | `legal.publish`（オーナー限定）            |

`:kind` は `terms` / `privacy` / `tokushoho`。

⚠️ **削除の経路は存在しない。**
⚠️ 下書きは種類ごとに 1 つなので、**下書きの ID を画面に持たせない**。
持たせると、古い画面から別の下書きへ書き込む余地が生まれる。

---

## 5. 画面

| 経路                                               | 用途                             |
| -------------------------------------------------- | -------------------------------- |
| `/legal/terms` `/legal/privacy` `/legal/tokushoho` | 公開ページ。フッタから常に辿れる |
| `/admin/legal`                                     | 3 種類の入口                     |
| `/admin/legal/:kind`                               | 下書きの編集・公開・これまでの版 |

- 本文は限られた印だけを解釈する（`## ` 見出し、`- ` 箇条書き、空行で段落）
- **HTML 文字列を組み立てない。** `renderLegalBody` が構造を返し、React の要素として描く
- 施行中の版が無ければ「準備中です」と出す。**空の文を作って取り繕わない**

## 6. まだできないこと

| 事項                                                                   | レジスタ |
| ---------------------------------------------------------------------- | -------- |
| 規約・プライバシーポリシーへの**同意記録**（いつ・どの版に同意したか） | `UD-126` |
| 改定を既存の購入者へ知らせる経路                                       | `UD-127` |
| 出品者ごとの特商法表記（マーケットとしての表示義務）                   | `UD-111` |

⚠️ 同意記録が無いということは、**「この購入者はこの版に同意した」と言えない**ということ。
同意をどの時点で取るか（会員登録／購入）と、改定時に再同意が要るかは業務の決定なので、
実装の前に決める必要がある（`UD-126`）。
